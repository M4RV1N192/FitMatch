# Rolle von KI in der Softwareentwicklung


## 1. Use-Case Wahl
Erstellung von User Stories und Testfällen für neue Features

KI wird genutzt, um aus kurzen Feature-Beschreibungen automatisch:

- User Stories
- Akzeptanzkriterien
- einfache Testfälle  

zu generieren.


## 2. Prompt Entwurf nach R-K-A-B-C

### Rolle:
Du bist ein erfahrener Software Engineer und Product Owner.

### Kontext:
Das Projekt „FitMatch“ ist eine Plattform zur Vermittlung von Trainingspartnern basierend auf Sportart, Standort und Leistungsniveau.

### Aufgabe:
Erstelle:

1. eine User Story
2. drei Akzeptanzkriterien
3. zwei Testfälle

für das beschriebene Feature.

### Beispiel:
Feature: Nutzer sollen andere Sportler nach Sportart filtern können.

### Constraints:
- kurze und klare Formulierungen
- Scrum-kompatible User Story
- Testfälle im Given-When-Then-Stil


## 3. Output evaluieren

### Output 1:
**User Story:**  
Als Nutzer möchte ich Sportler nach Sportart filtern können, damit ich passende Trainingspartner einfacher finde.

**Akzeptanzkriterien:**  
- Nutzer können eine Sportart auswählen  
- Die Ergebnisliste wird gefiltert angezeigt  
- Mehrere Sportarten dürfen ausgewählt werden  

**Testfälle:**  

**Testfall 1:**  
**Given:** mehrere Nutzerprofile existieren  
**When:** nach „Fußball“ gefiltert wird  
**Then:** werden nur passende Profile angezeigt  

**Testfall 2:**  
**Given:** kein Nutzer passt zum Filter  
**When:** die Suche ausgeführt wird  
**Then:** wird eine leere Ergebnisliste angezeigt  

### Output 2:
**User Story:**  
Als Nutzer möchte ich Trainingspartner in meiner Nähe sehen, damit gemeinsame Treffen einfacher organisiert werden können.

**Akzeptanzkriterien:**  
- Standort des Nutzers wird berücksichtigt  
- Ergebnisse werden nach Entfernung sortiert  
- Nur öffentliche Profile werden angezeigt  

**Testfälle:**  

**Testfall 1:**  
**Given:** mehrere Nutzer befinden sich in unterschiedlichen Städten  
**When:** ein Nutzer die Partnersuche startet  
**Then:** werden zuerst nahe Nutzer angezeigt  

**Testfall 2:**  
**Given:** ein Profil ist privat  
**When:** die Suche ausgeführt wird  
**Then:** erscheint das Profil nicht in den Ergebnissen  

### Bewertung:
|     **Kriterium**     | **Bewertung** |
|:---------------------:|:-------------:|
| Verständlichkeit      | gut           |
| Struktur              | gut           |
| Fachliche Korrektheit | gut           |
| Vollständigkeit       | ausreichend   |
| Anpassungsbedarf      | gering        |


## 4. Risiken und Kontrollen

### Risiken und Kontrolle:
| **Risiko**                 | **Kontrolle**              |
|----------------------------|----------------------------|
| ungenaue Anforderungen     | manuelle Review im Team    |
| fachlich falsche Testfälle | Prüfung durch Entwickler   |
| zu generische Outputs      | präzisere Prompts          |
| fehlender Projektkontext   | Kontext im Prompt ergänzen |
|                            |                            |

### KI-Einsatz im Team:
KI unterstützt das Team bei:

- Erstellung von User Stories
- Generierung von Testfällen
- Code-Skizzen und Dokumentation
- Architektur- und Diagrammideen

Die finale fachliche Prüfung erfolgt immer durch das Team selbst.
